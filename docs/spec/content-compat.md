# Content processing compatibility

Specification: Kotlin `2bdd3c58b`, `help/book/ContentProcessor.kt`, `ContentHelp.kt`, `data/entities/Book.kt`, `BookChapter.kt`, and `ui/association/BookSourceImport.kt` / `SourceImportReplacement.kt`.

## Conversion and segmentation

`ChineseConverter` uses the unmodified OpenCC ver.1.1.9 ST/TS character and phrase tables, longest phrase first and first alternative. See `Resources/OpenCC/PROVENANCE.md` for the pinned commit, hashes and license. This deliberately follows the approved OpenCC data decision; HanLP versions can differ. Modes 0/1/2 mean unchanged/traditional-to-simplified/simplified-to-traditional. `java.t2s` and `java.s2t` share the same implementation.

Content processing removes a duplicate leading title, optionally resegments, converts Chinese, protects special HTML, applies content rules, restores HTML, then formats paragraphs. Display titles convert before title rules. The duplicate-title fallback uses the unconverted replacement title. Raw chapter cache is preserved across preference changes.

`ContentHelp.reSegment` ports the Kotlin UTF-16 indexing and quotation heuristics, including its random long-paragraph splitting. Tests inject fixed random values. Twenty-two sentence samples and six random-branch samples were generated by running the actual Kotlin file on a JVM, replacing only `Math.random()` with 0.5/0/0.99. They are stored as assertions in `ContentHelpTests`. Java whitespace classes use ASCII semantics. Swift invalid reverse slices throw an explicit range error instead of trapping.

## Special HTML and defaults

`<usehtml>...</usehtml>` fragments survive replacement and return as separate single-line paragraphs. The option can be disabled. This protection occurs after conversion/resegmentation, as in Kotlin; it does not promise byte preservation across those earlier transforms.

An explicit per-book `useReplaceRule` wins. Otherwise image books and local EPUB disable replacement; other books use `replaceEnableDefault`. Source-only rules do not run on chapter text.

The Kotlin `removeSameTitleCache` is a set of `.nr` marker files disabling automatic title removal for a chapter, not a list of previously processed content. `BookHelp.setRemoveSameTitle` persists/removes these markers using the shared chapter cache naming; processing checks disk so toggles also affect existing processors. The reader receives the same cache directory. The reader control is part of U6.

## Rule updates

The reader shares a bounded 32-entry processor pool, keyed by book name/origin and processing configuration. Each processor serializes processing and rule updates. `upReplaceRules` refreshes existing pooled instances and resets timeout-disabled rules when rule definitions change. Eviction limits retained memory; a later access rebuilds the processor from the current rule snapshot.

Enabled-rule database observation triggers reader reflow, preserving raw cache and current reading position. Updates during chapter loading are deferred until loading finishes. Every asynchronous rule fetch checks the layout request generation before starting a new render, so obsolete refreshes cannot cancel the latest layout.

## Source JSON replacement

`scopeSource` applies to serialized book/RSS source import, not to a third content-rule scope. Matching uses original source name/URL, literal case-insensitive containment, optional exclusions and sort order. It does not use SQL LIKE wildcard semantics. Replaced data must decode to one valid source; invalid JSON, empty source URLs and failed rules abort import with an actionable error.

The Android `importReplaceSource` preference defaults to false. The import UI exposes the same opt-in switch and persists it. Book source previews reflect transformed identity/counts; RSS applies the selected mode before saving. No matching rules means the original source is returned without JSON reserialization. JSON serialization field order can differ from Gson; rules depending on whole-object key order are not guaranteed portable.
