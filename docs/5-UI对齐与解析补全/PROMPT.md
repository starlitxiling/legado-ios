# 需求（轮次 5 · UI 对齐原版与解析管线补全）

## 人类原话要点（2026-09-18）

1. 现状：iOS 版已经可以正常安装到 iPhone、可以正常阅读、坚果云（WebDAV）同步可用。
2. **整体 UI 希望和原来（Android 版 Legado）差不多。**
3. **很多解析都没有做好**：包括书源解析、添加书架、书籍本身的解析 —— 不单单是 TXT，还有 EPUB 等其他格式。
4. 本轮只要一份细致的整体计划，交给 Codex 执行；计划里 **整体 UI 风格必须说清楚**，**核心解析也必须说清楚**。
5. 计划提出的六项待确认（书架默认形态、阅读器设置面板范围、rar / 7z、书源回归集、真机次数、OpenCC 词表）：**「我希望都做，就是这样我能让他一直做」** —— 全部按最大范围定案，见 `PLAN.md` §8。

## 本轮目标

把 iOS 版从「功能面铺全的薄壳」推进到「视觉与行为都对齐 Android 原版的可日用阅读器」，分两条线并行：

- **解析线**：把书源规则引擎、JS 宿主、WebBook 四流程、内容净化、本地书格式（TXT / EPUB / UMD / MOBI / PDF / 压缩包）与书架逻辑对齐到 Kotlin 规格，消灭已知 P0 与整类缺失。
- **UI 线**：以 Android 原版的布局、尺寸、配色、交互为规格，用 SwiftUI 复刻主界面、书架、搜索、发现、详情、阅读器、书源管理、我的 / 设置。

## 不在本轮范围

- 书源类型 3（文件下载）/ 4（视频）。
- 应用内更新、悬浮窗、Quick Settings Tile、ContentProvider 对外 API 等 iOS 无对应能力的项。
- App Store 上架相关（签名、审核）。
